# Data disclosure report diffs the transcript against transiently re-fetched values, and always runs

The purpose of the disclosure report is to tell us which sensitive values (if any) leaked into the agent's transcript, so they can be rotated. We decided the middleware writes a classification log of every field it processes (item, field, type, decision) but never the real value, since persisting secrets to a log just creates a second secret store. At report time — which now runs automatically at the end of every session, not on demand — a script re-fetches the real value for each field marked "redacted" directly from 1Password, holds it in memory only, and does an exact substring search for it across the run's transcript. Any hit is reported as a leak with its location; no hits means a clean run. Known limitation: this only catches the literal value appearing verbatim, not a transformed/encoded copy of it.
